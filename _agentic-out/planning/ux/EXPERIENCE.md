# EXPERIENCE

本文档是 ai-subscribe 的实现级行为契约。视觉值不得在此重新定义，统一引用 [`DESIGN.md`](DESIGN.md)。完整设计理由见 [`../ux-design-specification.md`](../ux-design-specification.md)。

## Users And Journeys

### Users

| User | Primary need | Success signal |
|---|---|---|
| 个人 AI 开发者 | 在少量可解释情报中识别与当前项目相关的变化，并逐步校准规则 | 每天 ≤15 分钟；主情报流“有价值”≥70% |
| 技术负责人 | 在重大提醒后快速核验来源、影响和可信度，形成技术决策 | 通知“值得立即知道”≥80%；高优先级溯源完整率 100% |

### Named journeys

1. **首次启动并建立每日情报习惯：** 无注册、无 AI Key、无通知授权也能浏览演示数据；配置引导可跳过、可恢复；用户可手动固定关注仓库或创建 GitHub 项目发现订阅。
2. **重大提醒后的证据核验：** 设备本地判定并提交通知；深链直达详情；核对 AI、规则、原始事实和关联来源。
3. **校准雷达：** 从误报、漏报或规则入口调整关键词、排除词、来源权重和阈值；创建和校准 GitHub 发现条件，审查命中依据并控制自动关注；保存前预览风险，下一轮同步生效。
4. **故障中继续工作并自助恢复：** 离线或单源/AI/项目发现失败时继续使用缓存和既有 Release 结果；查看影响范围、数据安全、退避和恢复动作。

每条旅程必须在 Windows、iPhone、iPad、Android 手机和 Android 平板上具备等价任务路径。Windows 托盘是平台增强，不是移动端完成核心旅程的前提。

## Information Architecture

一级目的地保持一致：

1. 主情报流
2. 探索与被过滤内容
3. 搜索
4. 收藏
5. 来源
6. 雷达规则
7. 同步与诊断
8. 设置

平台导航合同：

| Platform/width | Primary navigation | List-detail behavior |
|---|---|---|
| Windows ≥1280px | Sidebar | 导航 + 列表 + 详情三栏 |
| Windows 1024–1279px | 压缩 Sidebar | 压缩三栏；保证详情最小宽度 |
| Windows 640–1023px | Sidebar/折叠导航 | 列表为主，详情进入独立视图或 Sheet |
| Windows <640px | 单栏导航 | 列表与详情单栈 |
| iPhone / Compact Android | 底部主导航 | Navigation Stack；筛选使用 Sheet/Bottom Sheet |
| iPad Regular | NavigationSplitView | 两栏或三栏，系统可折叠 |
| Android Medium+ | Navigation Rail/Drawer | Adaptive 列表—详情窗格 |

共同约束：

- 布局变化、旋转、分屏和窗口调整必须保留搜索、筛选、选中项、未提交输入和滚动锚点。
- 通知深链直接打开目标详情，并保留返回来源视图的路径。
- 主情报流不是必须清空的 Inbox；收藏不是“已读”；探索内容不是已删除内容。
- 当前视图搜索与全局命令分离：Windows `/` 聚焦当前搜索，`Ctrl+K` 打开全局命令。
- “来源”下明确分为“固定关注的 GitHub 项目”和“GitHub 项目发现”。发现订阅列表进入订阅详情与结果；项目发现结果不是 Release 情报，不进入主情报流。

## Primary Flows

### Flow 1 — First launch

1. 启动并读取当前设备本地状态。
2. 无真实数据时展示明确标识的演示数据；有数据时展示本地情报及最后同步时间。
3. 用户可立即搜索、筛选、打开详情和查看溯源。
4. 非阻塞邀请配置赛道、关键词、来源和刷新周期；每步可跳过并独立保存。
5. 配置第三方 AI 前，明确列出发送和不发送的数据；未确认时继续本地规则处理。
6. 进入主情报流；同步在平台允许时执行，失败不清空内容。
7. 跳过或离开引导后，用户可从设置根页固定的“配置引导”入口恢复；从主情报流到该入口不超过两次用户导航操作，已保存配置不得丢失。

验收：首启不出现注册墙、强制云账户、强制 AI Key 或强制通知授权；演示数据不会发送真实通知或进入验证指标；“配置引导”入口在设置根页可发现且两次导航内可达。

### Flow 2 — Daily scan and decision

1. 主情报流显示少量高价值动态和最后同步状态。
2. 用户选择条目；桌面原位更新详情，手机进入详情栈。
3. 首个详情视口按顺序展示：来源与标题、发生了什么、为什么重要、可能影响、重要程度、AI 置信度、主要操作。
4. 用户按需展开规则依据、原始事实、完整溯源和关联来源。
5. 用户打开原文、收藏、加入待研究或反馈；轻量动作保持当前上下文并可撤销。
6. 当日重点已处理后显示克制完成状态和探索入口，不要求清空普通候选。

验收：打开原文、收藏、反馈和查看评分依据均不超过两次操作；列表选择视觉响应接近即时；切换条目不清空列表状态。

### Flow 3 — Notification to evidence

1. 仅当当前设备已本地完成判断，且满足重大动态、溯源、阈值和通知授权时，才向操作系统提交通知。
2. MVP 不依赖远程推送；系统未提供后台机会时不承诺即时送达。
3. 点击通知后，在应用前台、后台或未运行状态均解析目标并打开对应详情。
4. 目标不存在时说明原因，并提供返回主情报流的安全入口。
5. 用户核对来源、时间、AI 标识、置信度、规则依据和关联来源，再打开原文或反馈。

验收：同一设备的同一情报/内容版本最多一次通知；过时内容进入主情报流而不补发误导性即时提醒；深链不得触发重复入库、分析或通知。

### Flow 4 — Rule calibration

1. 用户从情报详情、反馈统计或雷达规则进入对应配置。
2. 编辑赛道、关键词、排除词、来源可信度、提醒阈值或频率限制。
3. 实时显示修改摘要并防抖校验；表达式不可解析、数字/日期越界、下界大于上界、来源地址或标识无效、协议不受支持时，定位具体字段、说明修正方式并阻止保存。
4. 配置可解析但条件过窄时，以非阻断警告说明可能漏报的对象与原因；仅在用户明确确认后保存。固定风险样本分别覆盖“全部来源停用”和“当前设备的全部高可信候选被过滤”。
5. 不属于阻断性无效配置且未命中过窄风险时直接保存，不增加额外确认。
6. 保存后明确“下一轮同步生效”；历史情报、收藏和反馈不被改写。

验收：表达式无法解析、数值或日期越界、范围下界高于上界、来源地址或标识无效或协议不受支持四类阻断样本均不可保存并聚焦首个错误字段；两类过窄样本均可在确认后保存；正常样本无额外确认；保存失败保留全部输入、焦点和滚动位置；Phase 1 不依据反馈静默修改规则。

### Flow 5 — Failure and recovery

1. 保留缓存及已成功来源结果。
2. 全局仅显示离线/部分成功摘要；具体错误归属到来源或 AI 阶段。
3. 错误内容必须包含对象、失败阶段、时间、影响范围、数据安全状态和恢复动作。
4. 退避期间禁用重试并显示可再次重试的时间/条件。
5. 网络或服务恢复后继续有效任务；恢复结果原位更新并以非打断方式提示。
6. 导出诊断时剔除 API Key、授权头、完整正文和敏感提示。

验收：错误不覆盖可用内容；恢复后重复入库、重复分析和重复通知均为 0。

### Flow 6 — Content retention and deletion

1. 未收藏内容只长期保留元数据、必要摘录和分析结果。
2. 收藏时保存合法获得的正文快照并标明离线可用。
3. 取消收藏时，用户可选择删除正文及派生索引。
4. 删除确认明确列出将删除和允许保留的内容。
5. 删除完成后提供结果确认；搜索、详情和诊断不得再暴露正文。

验收：破坏性操作不可由手势独占；删除后正文、索引和可恢复残留为 0。

### Flow 7 — MVP source delivery readiness

1. 来源总览逐项展示 RSS/Atom、GitHub Release、arXiv 的交付与运行状态。
2. 每一类来源分别呈现未交付、未配置、可用、同步中、限流、失败、停用和待重试状态；失败不覆盖其他来源结果。
3. 三类来源全部达到候选构建验收条件前，不展示“Phase 1 已完成”或“全部来源就绪”。
4. 用户可以进入具体来源查看最后成功时间、影响范围、退避条件和独立恢复动作。

验收：三类来源逐项可见且均可独立诊断；汇总状态不得掩盖缺失或失败；任一类未达到门禁时 Phase 1 完成状态必须为阻塞。

### Flow 8 — Controlled mobile test distribution

1. 候选构建在构建/关于/诊断上下文展示平台、版本、签名状态、安装资格和授权范围。
2. 签名或安装资格无效时阻止进入受控测试分发，并说明具体原因和修复路径。
3. 分发前检查七类披露：设备本地数据、系统权限、公开来源、第三方 AI 外发数据、正文保留与删除、诊断范围、无云备份或跨设备同步。
4. 用户可从首次 AI 授权、设置和分发说明再次查看适用隐私内容；界面声明必须与实际行为一致。

验收：有效签名且安装资格有效的候选构建方可交付给授权测试账户或设备；七类披露缺一即阻塞；分发状态不得进入主情报流或伪装成情报优先级。

### Flow 9 — Sync result consumption

1. 每轮同步结束后保留可消费结果摘要：完成时间、来源级成功/失败、本轮候选数量和最小规范化条目入口。
2. 部分成功时先展示已成功来源的条目，同时指出失败来源、影响范围和独立重试动作；不得把整轮标为失败。
3. 零候选时明确“同步完成但没有新候选”，展示已检查来源和下一步，不伪装为错误或空白页。
4. AI 未配置、等待或失败时，用户仍可查看规范化条目的标题、来源、时间、链接和同步结果；AI 状态只附着于分析区。

验收：完整成功、部分成功、零候选和 AI 失败四种样本均能从结果摘要进入最小规范化条目或来源诊断；任何一类都不依赖 AI 才可消费同步结果。

### Flow 10 — Personal processing state

1. 用户可将条目标记为未查看、已判断或待研究；每次动作立即显示当前状态并允许在三态间转换。
2. 仅浏览列表或打开详情不得自动改变处理状态，也不得自动收藏、自动反馈或自动进入待研究。
3. 收藏/取消收藏不改变处理状态；处理状态变化也不改变收藏、列表选择或 AI 分析状态。
4. 搜索、筛选和重新启动后，当前设备上的处理状态仍可见；筛选导致条目即将退出当前视图时遵守上下文保持规则。

验收：三种处理状态与收藏/未收藏构成的六种组合均可独立建立、持久化和恢复；价值反馈与 AI 状态也不覆盖处理状态。

### Flow 11 — Windows repeated launch

1. 同一 Windows 用户会话中首次启动创建唯一可交互应用窗口。
2. 窗口可见、最小化或隐藏到托盘时再次启动，均显示并聚焦现有窗口；保持当前目的地、选择、筛选和未提交输入。
3. 系统不得出现第二个可交互实例；若平台拒绝直接抢占焦点，则使用标准任务栏注意反馈并保持现有窗口可恢复。

验收：正常窗口、最小化、托盘隐藏三种前置状态下重复启动，进程/窗口层面始终只有一个可交互实例，现有会话状态不重置。

### Flow 12 — GitHub project discovery and monitoring control

1. 用户从“来源 → GitHub 项目发现”创建订阅，配置名称、赛道、主要语言、Topic、Star/Fork 当前门槛，以及可选绝对/比例增长条件和观察窗口。
2. 保存前显示完整组合逻辑：不同维度同时满足、同一维度任一匹配；字段无效沿用阻断错误，合法但过窄沿用风险确认。
3. 首次有效增长观测只显示“增长基线已建立”；至少两个带时间戳的有效值后才分类增长，起始值为 0 时不使用比例增长命中。
4. 完整执行后，结果按“新发现项目”和“新符合条件项目”分类，逐项展示命中条件、实际值与观测时间；符合条件项目自动纳入设备本地 Release 监控。
5. 同一仓库被手动关注、多个订阅命中、重命名或转移时，只保留一个项目和一个有效 Release 监控对象，但保留全部订阅命中依据。
6. 用户可忽略当前订阅中的项目、停用自动关注或转为固定关注；界面在动作前说明其他有效关注及历史数据是否继续保留。
7. 发现订阅停用、条件失配、项目忽略或发现失败不得删除 Release、反馈、收藏等历史数据，也不得阻断既有项目的 Release 同步。
8. 发现运行明确区分成功有结果、成功零结果、部分完成、限流等待与失败；部分分页失败或限流不得显示为成功零结果。

验收：固定样本中的匹配、分类、依据、身份合并、三类控制和历史保留与 NFR54 预期 100% 一致；发现超时、限流、无效响应或部分分页失败时，错误只归属对应订阅，既有 Release 结果保持可见、可用且不重复。

| GitHub 发现订阅 | 未配置、草稿、校验中、启用、停用、执行中、保存失败 | 创建、编辑、启停、立即执行（允许时） |
| GitHub 发现结果 | 新发现、新符合条件、增长基线、已知命中、空结果、部分完成 | 展开依据、查看仓库、审查关注状态 |
| GitHub 项目关注 | 自动关注、自动关注已停用、固定关注、此订阅已忽略、多订阅命中 | 忽略、撤销忽略、停用自动关注、转固定关注 |
| GitHub 发现诊断 | 成功有结果、成功零结果、部分分页失败、限流等待、无效响应、超时、恢复中 | 查看影响、等待退避、重试、打开既有 Release 结果 |

## Interaction Behavior

### Selection and context

- 列表选择、三态处理状态、收藏、价值反馈和 AI 分析是独立维度；选择不得暗示业务动作，收藏不得暗示待研究或已判断。
- 桌面选择条目后原位更新详情；切换条目后详情回到顶部，列表滚动、筛选和焦点保持。
- 条目因刷新消失时说明原因并选择相邻项，不静默跳转。
- 当前筛选会排除刚处理的条目时，保留至用户刷新或离开视图，并说明状态变化。

### Search and filters

- 搜索作用域必须可见；输入防抖更新，不显示整页等待。
- 搜索元数据、必要摘录及当前可用的收藏正文，不得暴露已删除或未获准保存的全文。
- 启用条件以可移除状态项展示，并始终提供“恢复默认”。
- 排序变化不清除搜索、筛选或选择；后台新内容不使当前列表突然跳动。

### Commands and shortcuts

- Windows/外接键盘：方向键或 `J/K` 移动选择，`Enter` 进入详情，`O` 打开原文，`S` 收藏，`F` 打开反馈，`Esc` 关闭浮层或返回。
- 快捷键不得在文本输入控件中截获正常输入；所有快捷操作必须有菜单或按钮等可见等价入口。
- iOS/Android 遵守系统返回、预测性返回、手势、深链和焦点恢复；手势不是唯一入口。

### Feedback and asynchronous actions

- 收藏、反馈和规则保存先显示明确进行状态，成功后保持上下文；可逆动作提供撤销。
- 异步按钮保持尺寸稳定并显示进行中标签；禁止重复提交。
- 局部加载只覆盖目标区域，已有内容继续可操作。
- Toast/Snackbar 不承载必须阅读的信息；关键错误和数据后果保持可见。

### Forms and overlays

- 标签、说明和错误程序化关联；placeholder 不是标签。
- 保存失败保留输入；首个阻断错误获得焦点。
- Overlay 打开后焦点进入合理目标，Tab 被限制，Esc/平台返回关闭后恢复到触发器。
- 原则上不嵌套 Overlay；关闭 Dialog/Sheet 前不得静默丢弃脏数据。
- 阻断性无效配置在字段级显示错误、禁止保存并聚焦首错；过窄配置在摘要级显示漏报风险并要求明确确认；正常配置不得经过风险确认层。

### Setup reachability

- 设置根页入口名称固定为“配置引导”，并显示未开始、进行中、已跳过或已完成状态。
- 从主情报流到该入口最多两次用户导航操作；入口不得仅存在于首次启动、搜索结果、Tooltip 或帮助文档。
- 跳过、返回、关闭应用或平台生命周期中断后，已完成步骤和已保存字段原样恢复。

### Windows activation

- 再次启动是“显示并聚焦现有窗口”命令，不创建新的导航栈、会话或可交互窗口。
- 恢复现有窗口时保持当前页面、列表滚动、选择、筛选和未提交表单；不得重新播放首次启动或配置引导。
- 无法直接获得前台焦点时使用系统允许的任务栏注意反馈；用户激活后焦点进入现有窗口的合理位置。

### Device-local boundary

- 配置、收藏、反馈、凭据和历史情报只影响当前设备。
- 首次使用、设置、清除数据、卸载和迁移相关界面明确说明 MVP 无云备份、跨设备同步或自动迁移。
- 界面不得因相同用户身份暗示另一设备会自动出现变化。
- 作用域文案应明确写“此设备”，例如“删除此设备上的正文”或“仅修改此设备的来源设置”。
- 操作系统直接卸载无法可靠由应用拦截；相关数据后果通过设置、隐私说明和平台标准分发披露持续表达，不设计虚假的应用内卸载确认门禁。

### GitHub discovery behavior

- 发现订阅表单必须展示实际组合逻辑，不根据控件位置隐式推断 AND/OR；增长条件始终附带基线和零基数说明。
- 发现分类、关注状态、发现运行状态和 Release 同步状态是四个独立维度；任何状态变化不得静默覆盖另一维度。
- 忽略仅作用于当前设备和当前订阅；停用自动关注只暂停由自动发现维持的 Release 同步；转固定关注后不再依赖原订阅。每个动作必须说明其他有效关注是否仍让 Release 同步继续。
- 固定关注优先于自动关注。手动与自动重叠、多个订阅重叠及仓库身份变化只追加依据，不创建第二项目或第二监控开关。
- 发现列表更新保持当前订阅、筛选、项目选择、依据展开与滚动位置；恢复后不得把旧结果重新标成新发现。

## System States

### Empty

每个空状态必须说明：为什么为空、当前搜索/筛选、数据新鲜度或同步状态，以及至少一个下一步。

- 首次无真实数据：展示明确标识的演示数据和“开始同步/配置来源”。
- 搜索无结果：显示查询和条件，提供清除或恢复默认。
- 今日重点完成：显示最近同步、下一同步（如可确定）及探索入口，不制造未读压力。
- 收藏为空：解释收藏会保存合法正文快照以供离线阅读。
- 发现成功零结果：明确“本轮发现已完成，没有符合条件的项目”，显示订阅条件、检查时间和调整条件入口；部分完成不得使用此空状态。

### Loading

- 首次加载使用与最终布局一致的 Skeleton。
- 刷新已有内容时保留内容，只更新局部状态。
- AI 分析时保留原始标题、来源和必要摘录，显示“等待分析/分析中”。
- 加载超过合理时间后切换为明确状态说明和可执行动作，不无限显示 Skeleton。
- 使用平台 busy/live 语义；高频进度变化不得反复打断屏幕阅读器。
- 发现执行中保留既有结果和 Release 状态；分页进度只更新订阅局部区域，不锁定来源管理或主情报流。

### Error

错误必须包含：对象、失败阶段、发生时间（可获得时）、影响范围、数据安全状态、系统下一步和用户可执行动作。

- 单源错误不回滚其他来源；支持独立重试。
- AI 错误不伪造兜底结论；保留原始内容并标记待重试。
- 离线是可继续工作的模式，外部动作暂停但缓存可用。
- 原文失效保留采集时元数据和收藏快照状态。
- 数据完整性异常阻止受影响写入，并说明恢复路径。
- 退避期间重试入口保持可发现但禁用，并解释恢复条件。
- GitHub 发现超时、限流、无效响应或部分分页失败只附着于对应订阅；错误必须说明既有 Release 同步未受影响，且不得改写为“没有符合条件的项目”。

### Success

- 成功信息包含动作和对象，例如“规则已保存，将在下一轮同步生效”。
- 收藏、复制诊断、轻量反馈使用非打断反馈并提供适用的撤销。
- 恢复完成原位更新来源、AI 队列和最后同步时间，不弹出阻塞 Dialog。
- 删除正文必须显示完成结果及仍保留的数据类别。
- 成功状态不得依赖绿色或短暂 Toast 单独表达。
- GitHub 发现成功同时说明结果分类数量和自动关注变化；仓库已经由其他订阅或固定关注监控时，成功反馈说明“已追加命中依据，未重复建立监控”。

## Accessibility Requirements

目标：WCAG 2.2 AA 加平台原生辅助技术门禁。

### Shared

- 正文对比度 ≥4.5:1；大文本和非文本控件 ≥3:1。
- 重要度、来源、AI、离线、部分成功和错误状态具有文字或图标，不只使用颜色。
- 每个核心控件有稳定可访问名称、角色、状态和值；视觉顺序与遍历顺序一致。
- AI 生成区、规则依据和原始事实使用语义标题，可由辅助技术快速定位。
- 异步操作使用 busy/live 语义；成功采用非打断播报，错误与对应字段程序化关联。
- 减弱动画设置生效；布局、状态和操作结果不依赖动画理解。
- 截断内容提供可访问的完整文本入口，不只依赖悬停 Tooltip。
- 核心流程不得使用时间限制；诊断倒计时不频繁播报。
- “配置引导”入口的可访问名称为“配置引导，{当前状态}”；处理状态以“处理状态，{未查看/已判断/待研究}”播报，并与“已收藏”、价值反馈和 AI 状态分别暴露。
- 阻断性配置错误与具体字段程序化关联并聚焦首错；过窄风险使用警告语义、说明可能漏报对象，确认与返回修改均可由键盘和辅助技术完成。
- 同步结果按完成时间、成功来源、失败来源、候选数量顺序形成语义摘要；零候选播报“同步完成，没有新候选”，不得只播报数字 0。
- GitHub 发现结果的可访问名称包含“仓库名称、发现分类、关注状态”；命中依据展开控件包含依据数量，增长依据按首值、末值、观察窗口和观测时间顺序播报。
- 忽略、停用自动关注和转固定关注均有可见等价动作；确认文案说明作用域、其他有效关注及历史保留，不依赖滑动、右键或颜色。

### Windows

- 仅键盘可完成首启、浏览、搜索、详情、收藏、规则保存、重试和删除确认。
- 可见焦点遵循 [`DESIGN.md`](DESIGN.md) 的 `focus.default`；不得存在焦点陷阱。
- Radix/覆盖层实现焦点进入、循环、Esc 关闭和触发器恢复。
- Windows 重复启动恢复现有窗口后移动辅助技术焦点到原有活动上下文；若仅能请求任务栏关注，不得误播报已创建新窗口。
- 验证 NVDA、Windows 高对比度、浅/深主题及 100%、125%、150%、175%、200% 缩放。

### Apple

- 支持 VoiceOver、Voice Control、Switch Control、Full Keyboard Access、Dynamic Type、Increase Contrast、Button Shapes 和 Reduce Motion。
- 默认触控目标以 44×44pt 为目标；小于目标的视觉控件扩大可点击区域。
- NavigationSplitView 折叠、分屏、Stage Manager 和方向变化后保持上下文。

### Android

- 支持 TalkBack、Switch Access、Voice Access、字体/显示缩放和 Reduce Motion。
- 核心触控目标不得小于 48×48dp。
- Compose Semantics 明确角色、名称、状态、动作、窗格和遍历顺序；检查合并与未合并语义树。
- 验证预测性返回、Window Insets、折叠/展开、多窗口和动态 Window Size Class。

## Implementation Handoff

### Required shared contracts

- `IntelligenceFeedItem`、`EvidenceDetailPanel`、`SourceProvenanceGroup`、`SyncHealthSummary`、`SyncResultSummary`、`ProcessingStateControl`、`RuleImpactPreview`、`ProgressiveSetupGuide` 的字段、状态、事件和可访问名称。
- 情报重要度、AI 处理、来源可用性、同步健康、权限、任务恢复和设备本地范围采用可判别状态；禁止矛盾布尔组合。
- 共享深链目标至少包含情报稳定标识和安全回退目的地；解析失败进入“目标不可用”状态。
- 所有写操作定义 idle/submitting/success/error 和幂等/重复提交行为。
- `SourceDeliveryReadiness` 必须以 RSS/Atom、GitHub Release、arXiv 三个独立状态计算 Phase 1 门禁，禁止仅使用一个汇总布尔值。
- `DistributionDisclosureStatus` 必须包含平台、构建版本、签名/安装资格、授权范围、七类隐私披露及阻塞原因。
- FR59/NFR52：同步完成必须产出可消费结果摘要和最小规范化条目入口，完整成功、部分成功、零候选与 AI 失败均有固定验收状态。
- FR60/NFR53：处理状态采用“未查看/已判断/待研究”三态可判别模型，并与收藏、选择、价值反馈和 AI 状态正交持久化；仅浏览或打开详情不得触发转换。
- FR61/NFR33：设置根页固定“配置引导”入口，从主情报流最多两次导航操作可达，恢复时保留已保存配置。
- FR62：阻断性无效配置四类、过窄风险两类和正常保存路径分别使用统一测量基线的固定验收样本，不得由实现自行合并分类。
- FR63/NFR35：同一 Windows 用户会话只有一个可交互实例；重复启动恢复并聚焦现有窗口且保持上下文。
- FR64/NFR54：共享 `GitHubDiscoverySubscription`、`GitHubDiscoveryResult`、`GitHubRepositoryIdentity`、`GitHubObservation` 与 `GitHubMonitoringState` 行为合同；覆盖条件组合、首次基线、新发现/新符合条件、命中依据、固定优先、忽略/停用/转固定、身份合并、历史保留及发现/Release 故障隔离。
- GitHub 发现与 GitHub Release 同步采用独立可判别运行状态；部分完成或限流不得映射为成功零结果，发现失败不得阻塞或隐藏 Release 成功结果。
- PRD 尚未定义自动关注容量上限与超限策略；实现不得自行声明无限容量或发明静默淘汰。若平台资源需要硬边界，必须先回到产品合同补充可见上限及超限行为。

### Platform implementation boundaries

- Windows 使用 shadcn/ui + Tailwind/Radix；Apple 使用 SwiftUI；Android 使用 Compose Material 3 Adaptive。
- 三端共享领域模型、事件语义、测试向量和设计令牌名称，不共享 DOM 或强制像素一致。
- 使用平台原生安全区域、系统返回、通知、凭据、分享和辅助功能；不得手工模拟平台行为。
- 当前 [`../architecture.md`](../architecture.md) 已完成；实现应遵守其中的平台原生边界、本地通知、三类来源、签名分发和设备数据隔离决策，不得削弱这里的体验合同。

### Verification matrix

每个平台至少验证：

1. 无注册、无 AI Key、无通知权限完成首次体验。
2. 搜索、筛选、选择并打开详情，布局变化后上下文不丢失。
3. 区分 AI、规则、事实并打开原文。
4. 收藏、反馈、撤销以及删除正文确认。
5. 修改规则、处理风险警告和保存失败。
6. 离线、单源失败、AI 超时、限流与恢复。
7. 通知前台/后台/冷启动深链及目标不可用回退。
8. 键盘或屏幕阅读器完成核心任务。
9. RSS/Atom、GitHub Release、arXiv 三类来源逐项完成配置、同步、失败隔离、独立重试和 Phase 1 门禁判断。
10. iOS/iPadOS 与 Android 候选构建验证签名/安装资格、授权对象及七类隐私披露；任一缺失时阻止受控测试分发。
11. 同步完整成功、部分成功、零候选和 AI 失败时均能消费结果并进入最小规范化条目或来源诊断。
12. 三种处理状态与收藏/未收藏构成六种组合，修改、重启和筛选后仍保持独立，浏览列表或打开详情不改变状态。
13. 从主情报流两次导航内进入设置根页“配置引导”，跳过或中断后恢复且配置不丢失。
14. 四类阻断性无效配置不可保存，两类过窄配置经确认可保存，正常配置无额外确认。
15. Windows 在窗口可见、最小化和托盘隐藏时重复启动，均只恢复并聚焦现有可交互实例且上下文不重置。
16. 创建含赛道、语言、Topic、Star/Fork 当前与增长条件的 GitHub 发现订阅；验证基线/首次发现/首次跨门槛分类、命中依据、手动与多订阅身份合并、忽略/停用/转固定、仓库重命名，以及发现故障不影响既有 Release 同步。

组件层使用 Storybook/Xcode Preview/Compose Preview 覆盖状态；行为层使用各平台 UI 自动化；最终以 NVDA、VoiceOver、TalkBack 和真实设备测试作为运行时门禁。现有 HTML 文件只是可切换视觉预览，不能作为上述行为验收证据。
