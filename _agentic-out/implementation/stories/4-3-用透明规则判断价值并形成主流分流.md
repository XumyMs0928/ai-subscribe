# Story 4.3：用透明规则判断价值并形成主流分流

状态：done

## Story

作为 AI 开发者，
我希望理解每条情报为何被评为某个重要程度或被过滤，
以便信任并校准雷达，而不是面对黑盒排序。

## 当前阶段交付覆盖层

- 当前只实现 shared Rust core、单一 SQLite owner 与 Windows RSS/Atom 最小闭环所需的规则结果；不新增页面、route、Tauri command、DesktopApi method 或 capability。
- 本 Story 产出 query-ready 的 `high_value | ordinary_candidate` 当前投影、重要程度和结构化解释；Story 4.5 必须提供可达的主流与普通候选入口，Story 4.6 必须展示相同规则版本、过滤原因及事实/规则/AI 分区。这是不可豁免的下游交接，不得让 Canonical AC4 掉地。
- GitHub Release、arXiv、GitHub discovery、AI provider/分析、通知、反馈学习、移动端运行证据继续 Deferred；只能声明 `Windows RSS minimum-loop PASS/FAIL`。
- 风险信号建议 assured；为遵守用户批准的快速 Phase 1，显式沿用 standard。readiness 旧快照与缺少系统级 test design 作为已知建议项，不降低本 Story 的 non-waivable gates。

## 验收标准

### AC1 — 共享核心生成版本化、逐因素可解释的规则结果

**Given** Story 4.1/4.2 已保存的 real RSS/Atom fact、provenance、稳定 identity/association，以及当前设备已提交的关注配置  
**When** shared core 使用显式评估时钟执行 V1 情报价值判断  
**Then** 只依据赛道匹配、来源可信度、新鲜度、技术影响证据和用户 include/exclude 配置生成 `rule_version`、配置 revision/hash、内容 revision、0–100 分、`low | medium | high` 重要程度及稳定排序的逐因素 reason codes  
**And** 结果不依赖 AI、网络、平台 UI、SQL 表达式或自由文本猜测；AI 未启用时只保留真实 `unavailable` 状态，不伪造结论。（FR19、ARCH-3）

### AC2 — V1 评分、重要程度与缺失证据策略固定

**Given** 一条可评估 RSS fact 与 `INTELLIGENCE_VALUE_RULE_VERSION = "rss-intelligence-value-v1"`  
**When** core 计算 V1 分值  
**Then** 固定权重为赛道 25、来源可信度 25、新鲜度 20、技术影响 20、用户规则 10，总分使用整数且限制在 0–100；重要程度固定为 `low=0..49`、`medium=50..79`、`high=80..100`  
**And** 缺失或无法可靠判断的维度得 0 并返回 `unknown`/`no_evidence` reason，不以当前时间、AI 文本、默认重要度或其他维度补分。（FR19、FR20）

### AC3 — RSS Phase 1 的规则语义与主流门控明确

**Given** 当前设备的 `AttentionConfigurationV1` 和 real RSS item  
**When** V1 引擎计算各维度及分流  
**Then** 赛道只按 enabled track 的规范化 id/name 对 `title + source_summary` 做与现有表达式语义一致的确定性文本匹配；来源偏好将配置别名 `rss` 规范为事实类型 `rss_atom`，并以 canonical source identifier 精确匹配 trust；新鲜度使用 `published_at ?? collected_at` 与显式评估时钟的固定 bucket；技术影响仅命中 V1 allowlist 的模型能力、开发框架、部署方式、成本、安全、技术选型有限词表，否则为 `no_evidence`  
**And** source preference 缺失/disabled、trust 不在 min/max、非空 include 未命中、exclude 命中、规则生效窗外、无 enabled track 命中或缺可靠 publisher/HTTPS provenance 均强制为 `ordinary_candidate` 并保存具体过滤原因；不得删除候选。（FR16、FR19、FR21、FR22）

### AC4 — 当前阈值形成高价值与普通候选投影

**Given** 一条规则评估已完成  
**When** 应用当前配置的 `alert_threshold`  
**Then** Phase 1 明确将其作为本地规则价值 cutoff：无硬门控且 `score >= alert_threshold` 为 `high_value`，其余为 `ordinary_candidate`；该字段在本 Story 不触发通知，未来通知可通过 additive contract 拆出独立门槛  
**And** ordinary candidate 必须至少保存一个具体过滤 reason（硬门控 reason，或 `score_below_threshold` 连同实际 score/threshold）；重要程度、来源可信度和未来 AI 置信度保持三个独立概念。（FR20、FR21、FR22）

### AC5 — 同步写入与配置重评保持原子、幂等和事实隔离

**Given** 新增、更新或未变化 RSS item，或当前设备规则配置成功改变  
**When** 来源事务或配置事务提交  
**Then** New/Changed/Unchanged 均确保每个 eligible real RSS item 恰有一个与当前 fact revision、configuration revision/hash 和 rule version 一致的 current evaluation；配置保存对全部 real RSS current projection 原子重算，失败回滚该配置与其规则结果  
**And** 阈值/配置/时钟变化只更新 `rule_evaluations` 派生投影，不删除或改写 `intel_items` facts、`intel_contents` source excerpt、`item_provenance`、4.2 associations、sync result snapshots 或 `analysis_results`。（FR16、FR21、ARCH-4）

### AC6 — 固定输入确定性、迁移恢复与平台不得重算

**Given** 相同 fact revision、configuration revision/hash、rule version 和评估时钟  
**When** 跨重放、应用重启或重复调用执行规则评估  
**Then** score、importance、disposition、matched tracks、factor results 与 filter reasons 字节级一致且 reason 顺序固定，重复 current row 和副作用均为 0  
**And** fresh/v1–v9 数据库安全升级至 v10 并保留 demo/real facts、provenance、association、AI 与 FTS；Windows 后续只消费 core projection，Apple/Android 运行证据 Deferred，任何平台不得重写评分。（NFR8、NFR12、NFR13、ARCH-3、ARCH-9）

## Dev Notes

### 权威数据流

RSS/Atom adapter → RawSourceCandidate → Story 4.1 normalized fact/provenance → Story 4.2 deterministic association → 同一来源 `BEGIN IMMEDIATE` → V1 value evaluator → `rule_evaluations` current projection → checkpoint/result/count/cursor/task commit。配置保存走 current configuration transaction → 同一 evaluator 批量重算 → config/rule projection 一起 commit。

### V1 规则裁决

- **赛道 25：** 任一 enabled track 的规范化 id/name 明确命中 searchable text 得25，否则0并门控 ordinary。
- **来源可信度 25：** canonical source preference 精确匹配且 enabled，贡献 `floor(trust * 25 / 100)`；缺失/disabled/超出 configured min/max门控 ordinary。
- **新鲜度 20：** 使用固定 bucket 20/15/8/0；published缺失只允许 collected fallback并解释，未来时间不额外奖励。
- **技术影响 20：** V1 六类有限词表有明示命中得20；无证据为0，暂不做强门控，避免 RSS Phase1 因缺少结构化 taxonomy 全部被过滤。
- **用户规则 10：** include为空或命中得10；非空未命中为0并门控 ordinary；exclude命中始终门控 ordinary。
- **重要程度：** low 0–49、medium 50–79、high 80–100；它是可解释等级，不等同于来源 trust 或 AI confidence。
- **分流：** 无硬门控且 score≥现有 `alert_threshold` 为 high_value；其余 ordinary_candidate。该字段在快速 Phase1同时充当本地价值 cutoff，但本 Story不生成通知；未来通知阈值拆分必须通过 additive contract/RCL，不能静默改变历史结果。

### 重评与历史策略

- current projection 以 item_id 为一行；不在本 Story建立无限 evaluation history。审计身份由 rule_version、configuration revision/hash、fact revision、evaluated_at 和结构化 reasons 完整给出。
- New/Changed/Unchanged source commit、成功 configuration change 会校验/刷新 current projection；仅墙钟自然流逝不在后台自动启动任务，下一次合法 core evaluation opportunity 按新 clock bucket刷新。
- fixed input包含显式 evaluation clock；测试不得读取真实 wall clock。生产边界只读取一次当前时间并注入整批，禁止逐行取时导致边界漂移。
- reason/factor vectors使用固定枚举顺序，不依赖 HashMap/SQL未排序结果。

- 文本先做 Unicode lowercase、连续空白折叠；ASCII 词按字母数字边界匹配，中文词按完整子串匹配，避免 `cost` 命中 `costume`。同一维命中多个词仍只计一次分，但所有去重后的 reason code 按下列类别/词表顺序保存。
- 默认赛道 alias：`ai_agents = ["agent", "agents", "智能体"]`；`foundation_models = ["foundation model", "large language model", "llm", "基础模型", "大模型"]`；`local_models = ["local model", "on-device model", "本地模型", "端侧模型"]`。自定义赛道只使用规范化 id（`_`/`-` 视为空格）和 name，不自动生成同义词。
- 技术影响类别与词表：
  - `model_capability = ["capability", "benchmark", "context window", "reasoning", "multimodal", "能力", "基准", "上下文窗口", "推理", "多模态"]`
  - `development_framework = ["framework", "sdk", "api", "breaking change", "框架", "开发包", "接口", "破坏性变更"]`
