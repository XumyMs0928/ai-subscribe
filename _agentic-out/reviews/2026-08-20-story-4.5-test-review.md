## Executive Summary

**Overall Assessment:** Good  
**Recommendation:** Request Changes

测试层次完整，31 个用例覆盖 Core 查询语义、游标安全、Tauri 边界、传输契约、React 交互和关键 E2E 旅程。测试没有硬等待、未模拟外部调用、随机输入或串行 E2E 组；隔离、fixture 和显式断言总体良好，50,000 行性能门也稳定低于 200ms P95。

合并前建议处理两个可靠性根因：`Last7d` 集成测试依赖真实系统时间，固定于 2026-08-18 的样本会在日历推进后自然失效；性能测试同时依赖墙钟阈值和固定证据路径，在高负载或并发测试进程下可能出现非代码回归。其余 CSS 定位与维护性问题可随同修复或进入紧随其后的测试债务 PR。

### Key Strengths

- 31 个测试跨越正确层级，Core 语义没有被 browser mock 冒充。
- 无 hard wait、无未 mock 外联、无随机数据，Playwright 使用框架原生等待。
- Rust 每测独立数据库、React 每渲染独立 QueryClient、E2E 每旅程独立 fixture。
- 50,000 行、30 次采样的两组 P95 分别约 62.409ms 与 92.58ms。
- 游标篡改、查询身份绑定、投影漂移、分页恢复与键盘焦点均有明确断言。

### Key Weaknesses

- `Last7d` 集成测试读取真实系统时钟，具有确定的未来失效日期。
- 性能门对宿主负载敏感，并使用固定的 evidence/temp 路径。
- 四处 `.feed-status` CSS 类定位把行为断言耦合到表现层。
- Tauri 命令 allowlist 在两个测试文件中重复维护。
- 仅 3 个 E2E 用例显式携带 P0；其余 28 个用例没有统一测试 ID/优先级标记。

## Critical Issues (Must Fix)

没有 P0 Critical 问题。以下三个 High 问题按 P1 处理，其中前两个是合并前可靠性修复项。

### 1. 固定样本会让 Last7d 测试随时间自然失效

**Severity:** P1 (High)  
**Location:** `crates/radar-core/tests/sync_tasks.rs:1184`  
**Criterion:** Determinism  
**Knowledge Base:** `test-quality.md`, `timing-debugging.md`

`candidate()` 将发布时间固定为 `2026-08-18T08:00:00Z`，但 `query_intel_feed()` 在 Last7d 路径读取真实系统时间。测试当前通过不代表未来通过。

当前模式：

```rust
let result = service.query_intel_feed(&combined)?;
```

建议把 clock/as-of 作为应用服务依赖或测试入口显式注入：

```rust
let fixed_now = parse_time("2026-08-20T08:00:00Z")?;
let service = IntelFeedService::with_clock(store, FixedClock::new(fixed_now));
let result = service.query_intel_feed(&combined)?;
```

这消除测试的日历过期点，并保持 Last7d 业务语义可验证。

### 2. 墙钟性能门会受宿主争用影响

**Severity:** P1 (High)  
**Location:** `crates/radar-core/src/application/intel_feed.rs:669`  
**Criterion:** Determinism  
**Knowledge Base:** `test-quality.md`, `timing-debugging.md`

`Instant::now()` + P95 阈值符合 AC7 的性能证据目标，但普通并行测试环境中的 CPU 调度、节能状态和同时运行的门禁会改变结果。已有观察也显示并发门禁时可越过 200ms，而隔离运行恢复到约 62/93ms。

建议保留 50k 查询计划和结果正确性断言，将墙钟阈值放入受控、串行的性能 job；若必须留在 `cargo test`，应至少通过专用测试标签/runner 保证无其他重负载门并发。

### 3. Tauri allowlist 在两处重复维护

**Severity:** P1 (High)  
**Location:** `apps/windows/src-tauri/tests/release_surface.rs:24`  
**Related:** `crates/xtask/tests/generated_contract_gate_negative.rs:309`  
**Criterion:** Maintainability  
**Knowledge Base:** `test-quality.md`

完整命令集合以不同格式出现在发布面断言和 xtask sandbox source 中。命令新增或重命名时容易只更新一处。

建议提取规范化命令清单供两类测试消费，例如共享 fixture/helper 输出 Rust handler 片段和集合断言，避免复制整条字符串。

## Best Practices Found

### 1. Core 语义在真实存储边界验证

`intel_feed.rs` 与 `sync_tasks.rs` 使用内存 SQLite 和确定性数据验证当前事实投影、HMAC 游标、稳定排序及无重复分页。这是正确的测试层级，不依赖浏览器 mock 证明 Core 行为。

### 2. UI 状态隔离充分

React 测试每次渲染创建独立 QueryClient，Vitest 启用 `restoreMocks: true` 并在 setup cleanup；不存在跨测试 cache/mock 泄漏的明显路径。

### 3. E2E 采用语义交互和显式外联断言

关键旅程主要通过 role/label/text 操作，使用 `expect.poll` 等待 Tauri 调用，并在旅程末断言 `externalCalls() === []`，避免硬等待与真实网络不确定性。

### 4. 性能证据数据完整

AC7 场景固定 50,000 行、page size 30、每组 30 个 raw samples，并记录 P95 与阈值；数据规模是需求本身，不属于无意义的大 fixture。
