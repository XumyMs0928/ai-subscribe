## Material fixes applied

- Hardened SSRF IPv6 ranges, redirect/HTTP/retry handling, absolute deadlines and bounded RSS/Atom parsing.
- Enforced feed roots, namespace binding, direct entry paths, encoding, HTTPS item URLs, stable identity and checkpoint invariants.
- Moved source preflight/probe behind a core Application seam; rejected invalid/stale intents before network access, replayed committed idempotent responses before probing, and bounded concurrent probes.
- Tightened DesktopApi state/identity/cursor/limit guards and fixed source form stale completion, conflict refresh and configuration blocking states.
- Replaced 32-bit UI idempotency hashing with SHA-256.
- Made Playwright source mocks stateful across reload and added the blocking failure path.
- Hardened evidence publication, source fingerprint coverage, project-relative/anonymized evidence fields and Playwright process cleanup.
- Executed RSS/Atom fixtures and source golden DTO shapes in xtask.

## Remaining blockers

1. No complete fake Resolver/Connector/Transport matrix for DNS rebinding, redirect-to-private, TLS, 304, 429, slow/cancelled and compressed responses.
2. `FetchIncrementalResult` still lacks the planned opaque adapter cursor and explicit new/changed/unchanged dispositions; there is no complete core-owned incremental Application harness/reopen proof.
3. Desktop mutation timeout cannot cancel or query the final native operation state; cache reconciliation only reduces the ambiguity.
4. Release-surface gates do not yet prove from the feature graph/final binary that test transport, localhost allow or test resolver code is absent.
5. Native RSS evidence still lacks a successful public-HTTPS save/reload and direct three-way zero-half-write verification.
6. Source page still needs explicit migration/read-only versus storage/network error presentation and broader component state coverage.
7. Browser zero-external-call interception does not yet cover every resource channel through context routing.
8. Story-specific automation, test review and traceability reports must be regenerated after implementation stabilizes.
