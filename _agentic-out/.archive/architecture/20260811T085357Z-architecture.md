# 架构决策文档

_本文档通过逐步协作发现构建，并在过程中持续补充各项架构决策。_

## 项目上下文分析

### 需求概览

**功能需求：**

PRD 包含 58 项功能需求，覆盖以下核心能力：

- RSS/Atom、GitHub Releases、arXiv 三类 MVP 信息源的配置、增量采集与来源级状态管理
- 情报规范化、确定性去重、原始事实与来源溯源
- 基于规则的筛选、评分、主情报流分流和重大动态判定
- 可选的 OpenAI-compatible AI 翻译、摘要、主题提取、重要度及置信度分析
- 情报浏览、搜索、筛选、详情核验、收藏和用户反馈
- 定时同步、手动同步、失败重试、部分成功和中断恢复
- 当前设备本地通知、深链接和免打扰控制
- 来源、规则、AI 服务、数据保留、隐私和诊断设置
- Windows、iPhone、iPad、Android 手机和平板的原生交互适配

这些功能形成一条清晰的数据流水线：

`来源采集 → 规范化 → 确定性去重 → 规则判断 → 可选 AI 增强 → 本地存储 → 通知判定 → 原生界面`

AI 不是采集和入库的前置条件。没有 API Key、AI 服务失败或设备离线时，核心聚合、检索、溯源与规则能力仍需完整工作。

**非功能需求：**

PRD 包含 51 项可测量非功能需求，主要架构驱动力包括：

- 50,000 条本地记录下，常用查询与筛选 P95 小于 200ms
- 首次启动至可浏览内容不超过 5 秒
- 网络、解析、存储、AI 和界面工作必须隔离，避免后台任务阻塞交互
- 单一来源失败不能中止其他来源或破坏既有数据
- 同一情报不得重复入库、重复分析或重复通知
- 所有重要判断必须保留来源、时间、原始字段和处理状态
- API Key、诊断日志、第三方 AI 数据发送和自定义 URL 需要明确安全边界
- 系统休眠、应用退出、移动端后台机会受限及异常中断后必须保持可恢复性
- Windows、iOS/iPadOS 和 Android 分别满足键盘、触控、屏幕阅读器、系统缩放及原生生命周期要求
- 受控测试分发、隐私声明、内容缓存和数据删除行为必须可验证

### 规模与复杂度

- 主要领域：跨平台本地优先原生应用、异构信息采集与 AI 辅助情报处理
- 复杂度等级：高
- 用户与租户模型：单用户、单设备数据域，无多租户
- 数据规模：单设备数万条记录起步，并需保留向更大本地数据集演进的空间
- 集成复杂度：中高；来源协议有限，但第三方格式、限流、游标和错误语义不一致
- 交互复杂度：高；桌面高密度三栏工作区、手机单栈、平板自适应多栏
- 实时性：近实时轮询和本地事件更新，不要求云端实时推送
- 合规复杂度：中等；不属于强监管系统，但涉及内容权利、隐私、第三方 AI 数据发送及应用分发规则
- 预计逻辑架构组件：12–15 个，包括领域模型、来源适配器、网络策略、同步调度、规范化、去重、规则引擎、AI 增强、持久化、搜索、通知、诊断、密钥管理和平台应用层

### 技术约束与依赖

- 支持 Windows 10/11 x64、iOS/iPadOS 17+、Android 10+
- 数据仅保存在当前设备，MVP 不提供账户、云后端或跨设备同步
- 各平台可采用原生 UI 技术，但情报、证据、规则、状态和错误语义必须共享统一领域契约
- Windows UX 基线为高密度三栏决策台；手机采用单栈与底部导航；平板采用自适应列表—详情布局
- 移动端后台同步属于 best-effort，系统未提供执行机会时不得承诺准时刷新或通知
- 通知只由当前设备在本地评估后生成，不使用远程推送
- RSS/Atom、GitHub Releases 和 arXiv 均为不可删除的 MVP 验收范围
- 自定义来源和第三方 AI 服务需要处理 SSRF、重定向、响应大小、限流、超时与敏感数据发送
- 技术研究中的 Tauri/Rust/React/SQLite 是 Windows 单平台时期形成的候选方案，不应直接扩展为跨平台最终决策；后续需要单独确定共享领域层和各平台实现边界
- UX 文件在时间戳上早于最新 PRD，但最新验证已将其作为输入并确认需求一致；架构阶段需以最新 PRD 的跨平台边界为最终约束

### 已识别的横切关注点

1. **跨平台一致性：** 共享领域语义、数据模型、状态机和验收行为，同时保留平台原生交互。
2. **本地优先与离线：** 网络和 AI 均为可选增强，本地缓存和核心操作始终可用。
3. **数据完整性：** 幂等同步、确定性去重、事务边界、迁移安全和崩溃恢复。
4. **来源故障隔离：** 每个来源独立记录游标、退避、限流、成功时间和错误状态。
5. **事实与 AI 分离：** 原始事实、规则判断和 AI 生成结果采用不同的数据生命周期与展示语义。
6. **安全与隐私：** 密钥保护、最小权限、日志脱敏、SSRF 防护和第三方数据发送同意。
7. **性能与资源控制：** 增量读取、分页、索引、后台任务限并发和 AI 成本预算。
8. **生命周期与调度：** Windows 常驻、移动端受限后台、睡眠唤醒及应用重启需要统一的可恢复任务模型。
9. **通知治理：** 通知阈值、去重、免打扰、深链接和平台权限变化必须保持确定性。
10. **可观测性与验证：** 来源级诊断、处理计数、失败归因和跨平台自动化/真机验证证据。
11. **可访问性：** NVDA、VoiceOver、TalkBack、键盘、指针、动态字体和触控目标作为发布门禁。
12. **内容生命周期：** 元数据、正文快照、索引、AI 结果和用户反馈需要独立保留及删除策略。
