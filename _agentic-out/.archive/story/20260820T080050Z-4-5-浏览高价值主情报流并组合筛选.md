# Story 4.5：浏览高价值主情报流并组合筛选

状态：review

## Story

作为日常使用者，
我希望浏览少量高价值情报并按多个条件快速缩小范围，
以便在有限时间内找到与当前决策最相关的内容。

## 当前阶段交付覆盖层

- 当前只实现 Windows + real RSS/Atom 最小闭环。默认展示 `high_value`，并在同一“情报”工作区提供明确可达的 `ordinary_candidate` 入口；普通候选不得被删除或伪装成错误。
- 当前必要筛选仅为赛道、来源、时间和重要度。Story 4.4 的处理状态、Story 4.8 的收藏及正文、Story 4.7 的全文搜索均不显示控件或占位。
- Story 4.3 的 score、importance、matched tracks、stream disposition 与 current projection 是唯一权威；Rust core 负责查询、规范化筛选、稳定排序和 cursor，Tauri/TypeScript/React 不得重算、重排或用 demo 字段兜底。
- Story 4.6 接力真实证据详情、规则原因与安全打开原文；本 Story 只保留稳定 `intel_item_id` 的选择/导航接缝，不宣称详情能力完成。
- GitHub Release、arXiv、AI、通知、反馈、移动端、盲人屏幕阅读器承诺、完整跨平台 100 次性能矩阵和 NFR6 十分钟完整产品内存旅程继续 Deferred；只能声明 `Windows RSS minimum-loop PASS/FAIL`。
- 风险信号建议 assured；为遵守用户批准的快速 Phase 1，显式沿用 standard。readiness 旧快照与系统级 test design 缺失作为已知建议项，不降低下列 non-waivable gates。

## 验收标准

### AC1 — Core-owned 高价值与普通候选分页投影

**Given** schema v10 中存在具备可靠 provenance 的 real `rss_atom` facts，以及 Story 4.3 生成的 current rule evaluations  
**When** core 执行 V1 feed query  
**Then** 默认只返回 `stream_disposition=high_value` 的当前投影，并支持在同一“情报”工作区显式查询 `ordinary_candidate`；demo、legacy 或不可靠/不一致 provenance 不得混入 real feed  
**And** `QueryIntelFeedInputV1`、`IntelFeedPageV1`、`IntelFeedItemV1` 为独立版本化合同；item 只含列表所需 identity、来源、标题、有限摘录、时间、importance、score、matched tracks、disposition 与真实 AI unavailable 状态，不含正文、完整规则原因、AI 输入、原文 URL 或任意 SQL。（FR31、FR21、ARCH-3）

### AC2 — 四维组合筛选和稳定排序

**Given** 用户选择赛道、来源、时间窗口、重要度中的一个或多个条件  
**When** 筛选生效  
**Then** 不同维度使用 AND，同一维度多值使用 OR；赛道按 `matched_track_ids` 的完整稳定 ID、来源按 `source_id`、重要度按 `low|medium|high`、时间按 `published_at ?? collected_at` 匹配，空数组表示该维度不限  
**And** Phase 1 时间窗口固定为 `all_time|last_24h|last_7d|last_30d`；默认排序固定为 `score DESC, item_id ASC`，平台不得客户端排序、全量过滤或以 publisher/标题子串代替稳定 identity。（FR32、ARCH-8）

### AC3 — 不透明 cursor、查询快照与配置一致性

**Given** 首屏、下一页、stream 切换、筛选变化或规则配置重评  
**When** core 生成或消费 cursor  
**Then** 使用 `LIMIT + 1` keyset pagination；cursor 绑定版本、stream、规范化 filter identity、rule version、configuration revision/hash、首屏捕获的 `as_of` 时钟及最后 `(score, intel_item_id)` 边界，并限制为最多 1024 字节  
**And** cursor 不暴露 offset/rowid；伪造、截断、超长、跨 stream/filter/config/rule/as-of 复用或边界记录不一致时返回稳定可恢复 validation error，UI 从首屏重查且不得静默跳项、重复或客户端去重掩盖后端错误。（ARCH-8、ARCH-19）

### AC4 — Windows 主流列表与普通候选入口

**Given** feed query 返回结果  
**When** Windows 渲染“情报”工作区  
**Then** 复用 Story 1.7 已验证的语义列表、roving focus、选择、滚动与响应式模式；每项展示来源/时间、标题、必要摘录、重要度文字、赛道文字，以及“高价值”或“普通候选”的非颜色文字状态  
**And** 启用条件以可移除 chip 呈现并始终提供“恢复默认”；不显示处理状态、收藏、反馈、AI 操作、通知、全文搜索或 O/S/F 等假功能。选择与 Enter 只传递稳定 `intel_item_id` 给 4.6 接缝，列表 DTO 不携带详情正文。（FR31、FR32、UX-DR2、UX-DR14）

### AC5 — 完整状态、局部恢复与上下文保持

**Given** 首载、带旧数据刷新、筛选空结果、本地已有内容但同步不可用、来源部分失败、无旧数据的阻塞查询失败或下一页失败  
**When** 页面更新  
**Then** 首载使用匹配最终布局的 Skeleton；刷新/分页失败保留已有内容并显示局部错误与重试；空态说明当前 stream/筛选、数据新鲜度或最近同步，并至少提供恢复默认、查看普通候选或前往来源同步中的合法动作  
**And** 刷新、排序、返回导航与宽度变化不得无故清除筛选、选择和滚动锚点；后台新内容不得让列表突然跳动；已选条目消失时说明原因并恢复相邻合法项。已有本地内容可零网络读取，但不得据此宣称完整离线 Epic 已完成。（UX-DR18、UX-DR19、ARCH-19）

### AC6 — 键盘、焦点、响应式和非颜色表达

**Given** 用户仅使用 Windows 键盘操作当前 Story 能力  
**When** 浏览、切换高价值/普通候选、打开/关闭筛选、移除 chip、恢复默认、选择并进入条目  
**Then** Tab/Shift+Tab、方向键或 J/K、Enter、Esc 可完成全部当前核心任务；输入控件不截获字符快捷键，overlay 正确进入/循环/关闭并恢复触发器焦点，所有快捷动作均有可见等价入口且无焦点陷阱  
**And** importance、disposition、error、selected/focus 均有文字、图标或边界表达且不只靠颜色；复用既有 Windows 断点并在布局切换时保持筛选、选择、焦点和滚动。本 Story 不新增 `/`、Ctrl+K、O/S/F 等尚无真实动作的快捷键。（UX-DR20、UX-DR24、NFR29、NFR30）

### AC7 — Windows 固定 50,000 条数据集性能门

**Given** 项目内固定、可复现、关闭同步和 AI 的 50,000 条 real RSS 数据集  
**When** 分别测量默认高价值首屏与至少一个常用四维组合筛选，每类按用户批准口径执行 30 次正式样本  
**Then** 从 core 调用/用户操作开始到首屏稳定可消费的 P95 均小于 200ms，并记录候选构建、Windows/硬件、SQLite/工具链版本、数据集 hash、前置条件、30 个原始样本与 P95  
**And** 查询使用 SQLite 索引、有界 DTO、blocking DB executor、cursor pagination 与有界 DOM；不得全量加载后在 TypeScript 过滤、排序或切片。Canonical 各平台至少 100 次和 NFR6 十分钟完整产品工作集矩阵留到 frozen RC / Story 9.4，不得假 PASS。（NFR2、ARCH-8）

## 完整产品 Canonical AC（Deferred 部分保留）

Epics 中 Story 4.5 的 canonical AC 继续有效，包括处理状态、收藏状态、各平台至少 100 次的 50,000 条性能矩阵、完整主流/搜索/详情/收藏/设置十分钟工作集旅程及移动输入方式。当前 Phase 1 只验收 Windows + real RSS/Atom 的高价值/普通候选、赛道/来源/时间/重要度四维筛选，以及用户批准的 30 次 Windows 性能样本；Deferred 能力不得以隐藏控件、默认字段、demo、browser mock 或单平台证据冒充完成。

## Dev Notes

### 权威数据流与字段来源

RSS/Atom → Story 4.1 fact/provenance → Story 4.2 association → Story 4.3 current `rule_evaluations` → core feed query/cursor → Tauri exact command → DesktopApi exact guard → TanStack Query → Windows list。
