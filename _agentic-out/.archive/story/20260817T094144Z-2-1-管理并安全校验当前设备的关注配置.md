# Story 2.1：管理并安全校验当前设备的关注配置

状态：review

## Story

作为 AI 开发者，  
我希望管理关注赛道、关键词、排除词、来源偏好和刷新策略，并在保存前理解错误或漏报风险，  
以便真实来源同步围绕我的技术判断需求可靠运行。

## 验收标准

### AC1：管理赛道并版本化保存到当前设备

**Given** 用户添加、修改、启用或停用关注赛道  
**When** 提交配置  
**Then** 核心验证名称、状态和重复冲突，并把有效配置保存到当前设备  
**And** 保存返回稳定版本；失败时保留全部输入、焦点和滚动位置。（FR4、ARCH-18）

### AC2：阻断性无效配置不得保存

**Given** 用户编辑关键词、排除词、来源、刷新周期、可信度或阈值  
**When** 配置命中表达式无法解析、数值或日期越界、下界高于上界、来源地址或标识无效或协议不受支持中的任一固定无效类别  
**Then** 系统禁止保存，并指出受影响字段、无效类别和修正方式  
**And** 焦点移至首个错误字段，错误与控件程序化关联且不只依赖颜色。（FR5、FR62、UX-DR28）

### AC3：过窄配置必须明确解释并确认

**Given** 配置可以解析但命中“全部来源停用”或“当前设备全部高可信候选被过滤”  
**When** 用户准备保存  
**Then** `RuleImpactPreview` 说明受影响条件和可能漏报的后果  
**And** 用户可以返回修改或明确确认保存；未确认前不得提交。（FR62、UX-DR6、UX-DR28）

### AC4：无风险配置直接保存

**Given** 配置没有阻断错误且未命中过窄风险  
**When** 用户保存  
**Then** 系统直接保存版本化配置  
**And** 不显示风险确认层或要求额外确认。（FR62、UX-DR28）

### AC5：确认回执不可重放或跨配置复用

**Given** 用户在过窄风险提示中确认保存  
**When** 配置在确认前被修改，或确认回执已过期、被使用或不匹配当前规范化配置  
**Then** 系统不得接受旧确认，并重新执行校验  
**And** 确认回执只绑定当前配置 hash 和验证器版本，不得持久化为永久绕过凭据。（ARCH-28）

### AC6：保存后续可消费的规则但不提前产生副作用

**Given** 用户配置来源可信度、提醒阈值、免打扰时段和提醒频率上限  
**When** 配置通过校验并保存  
**Then** 系统保存可供后续筛选和通知 Epic 使用的版本化规则  
**And** 本 Story 不生成通知、不依赖未来通知实现，也不静默修改历史情报。（FR6）

### AC7：重启与离线时仍可管理本机配置

**Given** 用户重新启动应用或处于离线状态  
**When** 再次打开设置或保存只需本地事务的有效配置  
**Then** 已保存配置保持可用，适用修改仍可离线保存  
**And** 界面明确说明配置只影响当前设备。（FR5、UX-DR9）

### AC8：完整表单状态、脏表单保护和键盘操作

**Given** 表单处于初始、已修改、校验中、警告、阻断错误、保存中、成功或保存失败状态  
**When** 用户使用鼠标、触控或键盘操作  
**Then** 状态、错误和保存结果具有稳定名称及非颜色提示  
**And** 离开脏表单前提示用户，保存失败不清除焦点、滚动位置或未提交输入。（UX-DR17、UX-DR19、UX-DR20）

### Windows-first 验收边界

- 本轮实施共享 Rust core、Windows Tauri/DesktopApi 和 Windows UI；Apple/iPhone/iPad/Android 的等价平台实现及运行证据继续 Deferred/N/A。
- 当前产品不承诺盲人屏幕阅读器支持；仍必须保证键盘可完成、可见焦点、无焦点陷阱、稳定控件名称、非颜色状态与等效视口可用。
- 真实 Windows 100%/125%/150%/175%/200% × 浅/深主题矩阵只在专用发布机或隔离 VM 执行；本 Story 不修改开发者日常系统主题、缩放、注册表或权限。
- 完成结论只能声明 `Windows milestone PASS/FAIL`，不得宣称跨平台 MVP 完成。

  - [x] 保存时始终重新规范化和验证；伪造、过期、已消费、风险集合变化、validator 变化、配置变化统一返回 AppError `validation.stale_validation_receipt`（表单级稳定原因 `stale_validation_receipt`），保留 draft 并重新进入校验，不映射为 internal。

## Dev Notes

### 强制数据流

```text
contracts/fixtures/configuration-validation
→ radar-core normalize/validate/risk/receipt
→ single SQLite owner + immutable configuration version
→ configuration/validate/save Application API
→ exact async Tauri commands
→ DesktopApi fail-closed guards
→ TanStack Query + local form draft
→ /rules + RuleImpactPreview
```

- Rust core 是默认配置、规范化、错误/风险分类、validator version、hash、receipt、revision 和持久化版本的唯一事实源。
- 前端即时提示只能改善输入体验，不能替代保存前 core 验证；React 不得自行判断“高可信”“全部来源停用”或表达式语义。
- 保存配置属于规则生效，不得乐观提交。UI 只有收到权威保存响应后才能展示新版本；保存失败不更新 query cache。
- 当前 source preference 仅是后续同步的配置输入。保存层只接受合同声明的公开来源标识及 `http`/`https`（产品优先提示 HTTPS），拒绝 `file:`、shell、路径和任意协议；本 Story 不探测 URL、不解析 RSS、不访问 GitHub/arXiv、不做 DNS/SSRF/TLS/重定向检查，真实网络安全策略属于 Story 2.2–2.4。

### 与 Story 1.8 的兼容边界

- 直接复用现有 `settings_metadata`、setup progress、`DemoStore`、SQLite v3、async Tauri blocking executor、DesktopApi timeout/error、集中 query keys、`/settings`、`/settings/setup` 和稳定 Router/QueryClient。
- Story 1.8 的 `track_ids`、`source_example_ids`、`refresh_cadence` 已是有效 core-owned 默认值；迁移后它们必须映射到 Story 2.1 的当前配置，不能留两套互相矛盾的事实。
- SetupProgress 仍只保存引导进度；业务配置进入 Story 2.1 的权威版本。跳过/稍后继续不能删除规则配置。
- 延续审查经验：超时重试复用幂等 key；exact revision；真实 UTC 时间；checked arithmetic；幂等表有界；fresh/current schema 启动即验证；真实 reopen/并发/回滚/迟到响应/焦点恢复测试。

### 技术与依赖

- 保持锁定：Rust 1.97.1/edition 2024、rusqlite 0.40.1 bundled、SQLite 3.53.4、serde 1.0.229、serde_json 1.0.151、Tauri core 2.11.5、CLI 2.11.4、React 19.2.8、TypeScript 5.9.3、Vite 8.2.1、TanStack Query 5.101.4、React Router 8.3.0、Tailwind 4.3.3、Vitest 4.1.10、Playwright 1.62.1。
- 不以“latest”升级任何版本。允许为 receipt/hash 在项目 Cargo.toml 增加精确锁定的直接依赖并更新项目 Cargo.lock；不得全局安装，也不得使用时间、PID、原子计数、FNV 或 DefaultHasher 冒充安全 entropy/hash。
- Tauri 官方说明重工作应使用 async command，当前实现继续把 SQLite 阻塞工作放到受控执行器，不能在主线程直接执行。
- TanStack Query mutation 成功后以权威返回值更新或失效关联 query；配置保存禁止 optimistic update。
- SQLite 同时仅允许一个 write transaction，保存使用显式事务并把 revision 检查、版本追加、current 切换、幂等响应和 receipt 消费作为一个应用级原子结果处理。
- 所有依赖、缓存、Rust/Node/Python 工具必须位于 `.toolchains/`、项目 store/cache 或项目 `node_modules`，不得影响全局环境。
