# Story 1.6：浏览安全隔离的演示情报

状态：done

## Story

作为首次使用者，  
我希望无需注册、云账户、AI Key 或通知授权就能浏览可信的演示情报，  
以便在不产生真实外部副作用的情况下立即理解产品价值。

## 验收标准

### AC1：可复现演示数据与明确标识

**Given** 当前设备为全新安装且没有真实情报  
**When** 用户首次启动应用  
**Then** 系统从共享 `contracts/fixtures/demo` 加载可复现的演示情报  
**And** 列表、详情及搜索结果中的每条演示记录均以文字或图标明确标识“演示数据”，不只依靠颜色。（FR1、FR2、NFR28、NFR29）

### AC2：独立 namespace 与零真实副作用

**Given** 演示记录已载入  
**When** 系统执行通知判定、AI 任务生成、验证指标汇总或真实记录去重  
**Then** 演示记录产生的通知、AI 外发和验证指标均为 0  
**And** `data_origin = demo` 使用独立 namespace，不与真实记录合并或形成确定性重复。（FR2、ARCH-9）

### AC3：离线、无 Key、无通知权限仍可使用

**Given** 应用处于无网络、无 AI Key 或通知权限未授予状态  
**When** 用户浏览演示列表、打开详情并执行基础筛选  
**Then** 所有任务均可完成且不出现注册墙、云账户连接、AI Key 配置墙或通知授权墙  
**And** 外部网络请求和系统通知提交均为 0。（FR1、NFR10、NFR28）

### AC4：候选构建首启性能

**Given** 各平台全新安装且无用户数据  
**When** 从用户发起启动计时至演示列表可滚动且详情可打开  
**Then** 当前 Windows-first milestone 至少 30 次候选构建样本的 P95 不超过 5 秒  
**And** 验收记录保存平台版本、设备、构建、数据集和实际结果。（NFR1）

> 2026-08-14 用户批准 Story 1.6 Windows milestone 将正式样本数由 100 调整为 30，以加快 Windows 功能落地；PRD NFR1 的最终跨平台发布门仍保留每个平台 100 次，待移动端恢复及发布验收时执行。

- Apple、iPhone、iPad、Android 手机和平板的 UI 与 AC4 性能样本保留为 Deferred Acceptance；不得标记为已实施，也不得据此宣称跨平台 MVP 完成。

## Dev Notes

### 强制数据流

```text
contracts/fixtures/demo（唯一权威、编译时嵌入）
  → radar-core fixture validation / idempotent seed / SQLite + FTS
  → Application queries（bootstrap/list/detail/search）
  → approved Tauri commands
  → DesktopApi
  → TanStack Query
  → Windows list/detail/search render state
```

### 架构护栏

- `radar-core` 是 SQLite、迁移、事务、查询和 demo origin policy 的唯一所有者；平台层不得拥有第二套业务规则。
- SQLite 使用 bundled rusqlite、WAL、`foreign_keys=ON`、有限 `busy_timeout` 和单串行写入边界；测试优先使用内存连接，避免时间/PID/OS temp 派生的非确定性路径。
- 共享 fixture 只能位于 `contracts/fixtures/demo`；Windows 测试通过核心或仓库相对路径读取，不复制到 `apps/windows`，生产通过核心内嵌资源读取。
- 演示数据不能仅由 UI 标签判断。origin 必须由核心专用 seed 建立，字段私有/受验证，任何平台传入 `data_origin=demo` 的通用写接口都属于违规。
- 当前 xtask/release tests 只允许 Story 1.2 壳和 `health_v1`；必须演进为 Story 1.6 的精确目录/command allowlist，不能删除 gate 或改成宽泛前缀。
- 现有 `health_v1`、DesktopApi Provider、AppError、timeout/request-generation、CSP/capability、SecretLease 和项目隔离工具链必须保持回归通过。

### Story 边界

- Story 1.6 交付的是安全、可复现、可离线查询的最小 demo 体验。
- Story 1.7 承担完整 `IntelligenceFeedItem`、`EvidenceDetailPanel`、三栏/详情栈、证据层级、完整键盘/NVDA 和主题/高对比度/200% 真实矩阵。
- Story 1.8 承担默认赛道、默认来源、配置引导、跳过/恢复和设备作用域说明。
- 不实现真实 RSS/GitHub/arXiv 同步、GitHub discovery、真实 AI、通知权限/提交、四周指标、收藏、反馈、处理状态、完整 FTS 产品搜索或外部浏览器打开。

### 依赖与版本

- 保持 Rust `1.97.1`、Tauri core `2.11.5`、CLI `2.11.4`、React `19.2.8`、TypeScript `5.9.3`、Vite `8.2.1` 和现有精确锁文件。
- 新增仅限本 Story 实际消费的精确依赖：`rusqlite 0.40.1` bundled、TanStack Query `5.101.4`，以及核心直接需要的锁定 serde/serde_json；不得使用 `latest`。
- 所有下载、缓存、Node/pnpm/Rust/Cargo/SQLite 工具和测试数据必须位于项目目录；不得调用或修改全局 Python、PATH、包管理器或系统设置。
- Tauri 官方 command 返回值经 serde 序列化，command 名必须唯一并显式注册；React Effect 在开发 Strict Mode 会额外执行 setup/cleanup，所有加载逻辑必须可重复且有清理。
