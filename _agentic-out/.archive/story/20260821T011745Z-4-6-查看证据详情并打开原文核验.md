# Story 4.6：查看证据详情并打开原文核验

状态：done

## Story

作为技术决策者，
我希望在单条情报中查看内容提炼、评分依据、完整溯源和关联来源，
以便在采取行动前核验事实与系统判断。

## 当前阶段交付覆盖层

- 当前只交付 Windows + real RSS/Atom 最小闭环：从 Story 4.5 的真实情报列表原位打开详情，查看本地事实、Story 4.3 当前透明规则、Story 4.1 溯源、Story 4.2 确定性关联来源，并通过系统浏览器打开安全原文。
- “内容提炼”只可展示来源提供的 `source_summary`/必要摘录及明确事实字段；不得把 `rules.value.explainable` 等内部 message key、demo 文案、列表摘录或模型生成文本冒充事实总结。
- AI 本阶段没有 provider、请求或生成结果。详情只能明确显示“本阶段未启用”或“未配置”，不得显示模拟结论、置信度、理由、等待动画或重试动作。
- Phase 1 原文入口采用比 canonical HTTP/HTTPS 更严格的 canonical **HTTPS** 目标。React/WebView 的每个原文动作必须提交稳定 `intel_item_id + provenance_id`；不得猜测 primary、按数组位置选来源、提交任意 URL、调用通用 shell/opener/file/HTTP capability或在 WebView 内加载文章。当前安全保证覆盖 HTTPS、userinfo/fragment/长度/localhost 与直接写出的私网、环回、link-local、reserved IP 拒绝以及 provenance 一致性，不声明实时 DNS 解析结果或站点可达。
- Story 4.4 处理状态、Story 4.7 搜索、Story 4.8 收藏/正文、Epic 5 AI、反馈、通知、GitHub Release、arXiv、Apple/Android 与完整移动/平板布局继续 Deferred；不得显示假控件或计入完成声明。
- 风险信号 `security + high-nfr + cross-artifact` 推荐 assured；为延续用户批准的 Phase 1 快速闭环显式采用 standard。readiness 旧快照与系统级 test design 缺失是已知建议项，但不得降低本 Story 的 URL 安全、数据权威、可访问性与 evidence gates。

## 验收标准

### AC1 — Core-owned 详情合同与事实/规则/AI 分区

**Given** 用户从 Story 4.5 列表以稳定 `intel_item_id` 打开 real RSS 情报  
**When** core 查询当前详情投影  
**Then** 独立版本化 `QueryIntelEvidenceDetailInputV1` / `IntelEvidenceDetailV1` 返回与当前事实版本一致的 source facts、可靠 provenance，以及独立的 rule/AI 子投影状态  
**And** DTO 明确分为 source facts、rule explanation、AI status、provenance 和 actions；事实只含标题、发布方、来源提供的可选摘要、时间等允许持久化字段。`rule_status: current | unavailable | stale`：只有规则同时匹配 fact revision 与当前 configuration/rule version 时才返回 score/importance/disposition/matched tracks/typed factors/filter reasons；缺失、漂移或畸形不得冒充当前规则，也不得阻断事实和 provenance。AI 固定为 `unavailable` 且 UI 显示“本阶段未启用”。任何缺失值为 optional/null 并显示“未提供”，不得推断、生成或读取未收藏全文。（FR16、FR20、FR30、FR34、NFR29）

### AC2 — 独立溯源记录与确定性关联来源

**Given** 当前条目至少存在一条可靠 primary provenance，并且可以存在零个或多个 Story 4.2 association members  
**When** 用户展开 `SourceProvenanceGroup`  
**Then** 单来源时完整显示 primary provenance；有关联时，primary 与每个 associated source 各自显示稳定 provenance identity、发布方、作者或“未提供”、原标题、显示用 HTTPS 地址、发布时间、采集/首次发现/最后更新时间、最后已知原文状态与 source kind  
**And** 只有存在 association 时才显示 `same_event + normalized_original_url + basis_version` 等已存确定性依据；不得按标题/摘要相似度扩组、跨组传递合并、把多个来源折叠成合成事实，或把 RSS 多来源误称为三种 adapter 已完成。结果按 primary first、其余稳定 ID 排序并使用共享来源上限；超界或损坏必须保留 primary facts/provenance，返回局部 `association_status=incomplete` 与稳定问题码，不得静默截断或阻断整页。（FR14、FR15、FR24、FR34、UX-DR4）

### AC3 — 稳定意图驱动的系统浏览器安全原文入口

**Given** 某 provenance 当前仍能由 core 解析为与 fact/content/provenance 一致、来自已持久化 provenance 且通过当前 canonical HTTPS 与禁止 literal host 规则的原文目标  
**When** 用户选择该来源的“打开原文”或使用可见等价快捷动作  
**Then** WebView 仅调用精确 `open_intel_original_v1({contract_version,intel_item_id,provenance_id})`；core 在执行时重新查库、验证 ID/来源归属/可用状态及 canonical HTTPS，不信任详情 DTO 中可见 URL，Windows Rust adapter 再用系统默认浏览器打开  
**And** 主 WebView location/CSP 保持本地，零文章 HTML/远程脚本/前端 HTTP/通用 URL IPC；不得追加或记录 secret、正文、prompt、Authorization/Cookie 或应用敏感 query，日志/错误中的 URL 至少移除 query/fragment。不得授予 WebView `opener:allow-open-url`、shell、file 或任意网络 capability；该本地校验不声明域名实时解析结果或站点当前可达。（FR35、ARCH-12、NFR16–NFR18）

### AC4 — 原文失效、离线与打开失败的可信局部恢复

**Given** 原文记录缺失、非 canonical/不安全、已标记 unavailable、设备离线或系统浏览器 adapter 返回失败  
**When** 用户尝试核验原文  
**Then** 阻止不安全 effect，保留事实、规则、溯源、选择和列表上下文；在对应来源操作旁说明受影响对象、最后已知/采集时状态、数据仍安全及“返回详情/稍后重试”等合法动作  
**And** 不以“数据库中有 URL”或“系统已接收打开请求”伪装当前公网可达；详情查询不得为探测可达性发起 HEAD/GET/DNS，也不得用 `navigator.onLine`、前端 ping 或网络监听推断领域事实。若没有权威 offline 状态，只显示最后已知原文状态和实际 adapter 错误；断网时仍保留本地详情。阻断详情查询错误与规则/association/单个原文 effect 局部错误必须分离，局部错误不得覆盖整页。（FR15、FR35、UX-DR17、NFR10、NFR32）

### AC5 — Windows 原位列表—详情与上下文保持

**Given** Story 4.5 列表已有 stream、筛选、分页、选择、焦点和滚动锚点  
**When** 用户单击/Enter 打开详情、切换条目、调整 Windows 宽度或 Esc/返回列表  
**Then** 宽桌面在同一“情报”工作区原位展示 `EvidenceDetailPanel`；窄 Windows 使用独立详情/Sheet 等安全回退；详情切换聚焦语义标题并回到详情顶部，返回后恢复触发列表项、筛选、选择与滚动，不重新挂载无关路由或产生额外 feed IPC  
**And** 稳定 route 为 `/intel/:intelItemId`，直接进入时按 ID 独立查询详情而不依赖目标仍位于当前 feed page；loading/refreshing-with-data/not-found/blocking-error/AI-unavailable/original-unavailable/open-error 状态完整，已有详情刷新失败保留旧数据，迟到响应不得覆盖新选择，条目消失时沿用 4.5 的相邻恢复并解释原因。移动单栈、平板分栏、旋转/分屏 canonical AC 保留为 Deferred。（UX-DR3、UX-DR11–13、UX-DR18–20）

### AC6 — 键盘、语义层级和非颜色核验

**Given** 用户只使用 Windows 键盘浏览当前 Story  
**When** 从列表进入详情、定位事实/规则/AI/溯源分区、展开关联来源、打开原文并返回  
**Then** Tab/Shift+Tab、Arrow/J/K、Enter、Esc 可完成全部当前核心任务；详情使用唯一标题和可定位 section headings，展开控件暴露 `aria-expanded` 与关联数量，原文按钮可访问名称包含来源和目标，所有动作均有可见入口且焦点可见、无陷阱  
**And** 事实、规则、AI、原文状态、错误和选中状态具有文字/图标/边界表达，不只靠颜色；视觉顺序等于操作顺序，Windows 既有响应断点、reduced-motion、高对比度与 100–200% 等效视口约束继续有效。本阶段不扩大为盲人屏幕阅读器支持声明。（NFR29–31、UX-DR20、UX-DR24）

### AC7 — 有界、只读、无隐式副作用的证据门

**Given** 详情和关联来源可从当前 schema v10 事实、规则与 association 投影读取  
**When** 重复查询详情、切换来源或打开/失败打开原文  
**Then** detail query 使用按稳定 ID 的有界只读 SQL，不新增 schema/缓存/第二规则模型，不写 SQLite、不联网、不调用 AI、不改变 Story 4.4 处理状态/收藏/反馈；详情 DTO 不进入 Zustand/localStorage，TanStack Query key 固定为 API identity + `intel_item_id`  
**And** open command 是唯一显式平台 effect，按 stable id 解析并返回不含 URL/secret 的有界 receipt；重复点击遵循 loading/disabled 或明确幂等/重复行为。测试必须证明 detail query 零写入/零 external call、raw Tauri invoke 仍只在 adapter、WebView URL 不变、release/contract allowlist exact。（ARCH-3、ARCH-12、ARCH-19）

## 完整产品 Canonical AC（Deferred 部分保留）

Epics 中 Story 4.6 的五条 canonical AC 继续有效，包括桌面、手机和平板各自原生列表—详情行为、旋转/分屏上下文保持、真实 AI 状态链和 canonical HTTP/HTTPS 原文策略。当前 Phase 1 只验收 Windows + real RSS/Atom 原位详情、事实/透明规则/溯源/确定性关联与更严格的 HTTPS 系统浏览器入口；移动布局、真实 AI、其他来源 adapter 与完整跨平台矩阵不得以 responsive browser mock、demo fixture 或隐藏入口冒充完成。
