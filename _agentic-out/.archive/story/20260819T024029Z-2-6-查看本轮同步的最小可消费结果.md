# Story 2.6：查看本轮同步的最小可消费结果

状态：review

## Story

作为日常使用者，  
我希望在单个或全部 RSS/Atom 同步结束后立即查看本轮计数、来源归属和最小成功结果，  
以便在没有 AI、评分、搜索或完整详情时也能确认本轮实际获得了什么。

## 验收标准

### AC1：单源结果可持久读取

**Given** 一个 RSS/Atom 来源完成同步  
**When** 用户查看该任务对应的本轮结果  
**Then** 核心持久化并展示 inserted、updated、skipped、failed 计数和本轮成功转换的最小结果列表  
**And** 每条结果至少包含 source_kind、publisher、original_title、可空 published_at、collected_at 和经校验的 original_url。

### AC2：全部同步按来源实例隔离

**Given** “同步全部 RSS/Atom”包含多个已启用来源实例  
**When** 各来源分别成功、零结果或失败  
**Then** `SyncResultSummaryV1` 按冻结的来源实例显示状态、四类计数和结果  
**And** 一个来源失败不得隐藏、合并或回滚其他来源已提交结果；界面不得暗示 GitHub Release 或 arXiv 已实现。

### AC3：结果不依赖后续能力

**Given** 没有 AI Key，或 AI 失败、排队、尚未评分，且搜索和完整详情尚未实现  
**When** 用户打开本轮同步结果  
**Then** 已提交计数和最小结果仍可见、可分页读取  
**And** 读取不触发 AI、评分、搜索、通知或新的来源网络请求。

### AC4：四类结果状态互斥且不误导

**Given** 固定 RSS fixture 分别产生有结果成功、零结果成功、部分成功或全部失败  
**When** 核心汇总本轮状态  
**Then** 状态严格互斥为 `succeeded_with_results`、`succeeded_zero_results`、`partially_succeeded` 或 `failed`  
**And** partial 显示已确认数据和失败范围，零结果不被显示为 partial/failed，items 为空不得替代权威状态判断。

### AC5：固定证据达到精确一致

**Given** 固定 RSS/Atom 响应覆盖新增、更新、跳过、解析失败和零结果  
**When** 执行结果落库、重放与读取测试  
**Then** 执行计数与结果计数一致率、最小字段完整率、失败来源归属正确率均为 100%  
**And** 假零结果、隐藏成功结果、跨来源回滚和同 run 重复结果均为 0。

### AC6：重启和离线仍可读

**Given** 本轮来源结果已经提交  
**When** 应用重启或设备离线后按明确 run identity 重新打开  
**Then** 从 `sync_runs`、`sync_source_results`、`sync_result_items` 一致只读投影恢复相同计数、结果和错误归属  
**And** 查询不以“最新时间”猜测 run，不访问网络，不依赖 AI。
**And** v7 新建 task 必须返回 `result_ref`；由 v1–v6 迁移且无法重建历史结果事实的 legacy task 返回显式 `null`，不得合成计数、条目或 publisher。

## 第一阶段边界

- 只实现 shared Rust core、Windows Tauri/DesktopApi 和 Windows UI；Apple/iPhone/iPad/Android Deferred/N/A。
- 当前来源类型只允许 `rss_atom`。DTO 保留未来分组扩展性，但不得返回 GitHub Release/arXiv 占位来源或声称三来源完成。
- Story 2.2 的 parser、安全 HTTP、Retry-After 和 checkpoint 是唯一实现；Story 2.5 的 task/job 状态机是唯一任务事实源。
- Story 4.1 才建立最终规范化情报与完整溯源；本 Story 不提前实现最终 `intel_items` 写入、规则、AI、FTS、搜索或完整详情。
- `sync_result_items` 只保存本轮成功转换所需的最小不可变快照，并以 `(source_id, stable_external_id)` 稳定关联当前 `source_entry_checkpoints`；Story 4.1 再增加 final item identity，不得在本 Story 预填或伪造最终情报关系。
- 不保存 feed 原始 payload、完整正文、prompt、密钥或 URL query 诊断；不增加 generic URL/SQL/file/shell command。
- 不启动 native GUI、不跑 30 次候选采样；这些只在第一阶段最终冻结 release candidate 时统一执行一次。
- 所有依赖、缓存和测试服务位于项目目录；禁止全局安装 Python/Node/Rust，禁止修改系统代理、证书、主题、缩放或权限。

- TaskId 表示执行生命周期，SyncRunId 表示一次可消费结果；二者一对一关联但不可混用。
- `source_entry_checkpoints` 仍是 Story 2.2 的增量身份事实；`sync_result_items` 是本轮最小读取快照；Story 4.1 才写最终情报并补 `intel_item_id` 关系。
- V1 可消费项必须同时具备非空 title 和经 core 校验的 HTTP/HTTPS original_url；publisher 由 core 从已验证来源 authority 生成稳定显示值。缺失/非法字段计入该来源 `failed` 且不生成成功 item；`New→inserted`、`Changed→updated`、`Unchanged→skipped`，UI不得自行映射或填默认值。
- 每来源独立事务保证失败隔离；run summary 是已提交来源投影的确定性聚合，不是一枚松散 success bool。
- 查询只读、分页且不访问网络；无 AI/Key/评分仍完整工作。
- 不新增依赖；继续使用项目已锁定 Rust/Tauri/rusqlite/React/TanStack Query/TypeScript/Vitest/Playwright 版本。
